# GrammarBar — project rules

Rules for any agent working in this repo. Keep it short and true.

## Commits — do this by default, without being asked

**Commit as work progresses, not in one batch at the end.** This is the owner's
standing preference.

- Commit after each coherent change: a feature working, a bug fixed, a doc
  rewritten, tests passing. If you are about to start a second unrelated thing,
  commit the first one.
- **Push after committing.** A local-only commit is not finished work.
- Prefer several small, readable commits over one large one. Do not amend or
  force-push a commit that already went to `origin` **unless** you are removing
  something that must not be published (see the licensing rule) — then amend and
  `--force-with-lease`, and say so.
- Write messages that explain **why**, not just what. State measured numbers when
  a change is justified by them.
- Never commit: build output (`/.build`, `/.build-xcode`), `GrammarBar.xcodeproj`
  (generated), `Bench/.venv`, model weights, secrets, or anything covered by the
  licensing rule below.

## Licensing — a hard constraint, not a nicety

**Never commit third-party corpus text.** BEA-2019 / LOCNESS is non-commercial
research/education only with no redistribution to third parties; JFLEG ships no
`LICENSE` file at all.

Git-ignored and must stay that way: `Eval/data/`, `Eval/golden.jsonl`,
`Eval/results/`, `Eval/RESULTS.full-corpus.md`.

`Eval/LICENSES.md` may quote licence terms — required reproduction, not a leak.

Before publishing anything, verify against the published state rather than the
working tree:

```sh
git clone <repo-url> /tmp/gbcheck && grep -rIl "some-corpus-phrase" /tmp/gbcheck
```

Also: `Eval/results/*.json` and `Bench/results/*.json` contain model *outputs*,
which can echo corpus input. They are git-ignored for that reason.

## Before declaring a change done

```sh
swift build 2>&1 | grep -E 'error:|warning:|Build complete'
swift test  2>&1 | grep -E 'Executed .* tests, with'
```

Both must be clean. If you touched the correction pipeline, also run the
first-party eval and confirm it has not regressed:

```sh
swift run GrammarBarEval --set Eval/golden.first-party.jsonl --label <something>
```

Baseline to hold: **17/20 wrong fixed, 18/18 already-correct unchanged, 0 failed,
0 meaning-changed.** See `RUNBOOK.md` for the full gate list.

## Invariants — do not break these

1. **Privacy:** the process handling user text has no network entitlement.
   `com.apple.security.network.client` is deliberately **absent** from
   `Resources/GrammarBar.entitlements`, not set to `false`. Do not add it.
2. **Meaning:** a correction must never change what the text says.
   `meaningChangedCases` is 0 in every recorded run. If it moves, stop and treat
   it as the highest-priority bug in the project.
3. **Verify, don't assume.** The SDK is the source of truth for Apple APIs — read
   the `.swiftinterface`, and compile-and-run a probe for anything runtime.
   Filesystem state is not availability. Never write a `switch` over an SDK enum
   you have not read, and always include `@unknown default`.
4. **Measure, don't estimate.** Numbers in `PLAN-v2.md` §0, `Eval/RESULTS.md` and
   `Bench/RESULTS.md` are measured. If you change behaviour, re-measure and
   update the number; do not hand-wave it.

## Never do these

- Hand-edit `GrammarBar.xcodeproj` — it is generated. Edit `project.yml` and run
  `xcodegen generate`.
- Ignore an `xcodebuild` "database is locked" error as a code problem. It is a
  stale build holding `-derivedDataPath`; `pkill -f xcodebuild`.
- Report a child agent's summary as verified fact. Check the artifact.
- Present an edit-distance-only validator result as a good correction. A small,
  confident, wrong edit scores *very* safe (an invented tense is ~0.17). Gate on
  the class of change, not its magnitude.

## Layout

`PLAN-v2.md` (design + measured findings) · `RUNBOOK.md` (build/run/test) ·
`README.md` (overview) · `recon/` (the original probe) · `Sources/GrammarBarCore`
(all logic) · `Sources/GrammarBar` (SwiftUI) · `Eval/` (regression harness) ·
`Bench/` (offline-model benchmark).
